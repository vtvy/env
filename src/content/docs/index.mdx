## Install mise

Ref: [mise.jdx.dev](https://mise.jdx.dev)

```
Install mise (https://mise.jdx.dev) on this computer end-to-end.

Requirements:
1. Detect the OS and shell (Windows / macOS / Linux; PowerShell, bash, zsh, fish, etc.).
2. Install mise with the official recommended method for that OS:
   - Windows: prefer Scoop (`scoop install mise`); if Scoop is missing, use winget (`winget install jdx.mise --accept-package-agreements --accept-source-agreements`).
   - macOS / Linux: prefer the official installer (`curl https://mise.run | sh`), or Homebrew on macOS if preferred (`brew install mise`).
3. Ensure `mise` is available on PATH in a new shell. Refresh PATH in the current session if needed.
4. Activate mise for the user’s default shell so it persists:
   - PowerShell: add `(&mise activate pwsh) | Out-String | Invoke-Expression` to `$PROFILE` if not already present.
   - bash: add `eval "$(mise activate bash)"` to `~/.bashrc` (or equivalent) if missing.
   - zsh: add `eval "$(mise activate zsh)"` to `~/.zshrc` if missing.
   - fish: add `mise activate fish | source` to `~/.config/fish/config.fish` if missing.
5. Do not overwrite existing profile content; only append activation if it isn’t already there.
6. Verify with `mise --version`. If a newer version is available, run `mise self-update` (or the package manager update path) when safe.
7. Report back briefly: OS, install method used, mise version, and which shell profile was updated (or that activation was already configured).

Constraints:
- Prefer non-interactive flags.
- Don’t change unrelated shell config.
- Don’t commit anything or modify git config.
- If installation requires admin/elevation or a missing prerequisite (e.g. Scoop, curl, Homebrew), explain the blocker and the exact next command the user should run.
```
